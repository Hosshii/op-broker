# Project Summary
- **Purpose**: Rust-based 1Password broker that runs on macOS (`broker` crate) to proxy `op read` calls for trusted clients over a Unix domain socket while enforcing an allowlist and strict file permissions. A companion CLI (`ctl` crate) runs on dev servers or containers to fetch secrets through the broker, keeping 1Password credentials off remote hosts.
- **Architecture**: Workspace crates include `broker` (daemon), `ctl` (CLI), and `crates/protocol` (shared tonic/prost definitions and helpers). Broker exposes a tonic gRPC service over a Unix socket, loads `config.json` allowlist, executes `op` via `std::process::Command`, and returns values. CLI communicates with the Unix socket (potentially via SSH reverse tunnel) and supports flags like `--socket`, `--nonce`, `--json`, `--quiet`.
- **Key Directories**: `broker/src` (main.rs, config.rs, op_client.rs, service.rs), `ctl/src/main.rs`, `crates/protocol/src/lib.rs` + `proto/opbroker.proto`, `configs/config.example.json`, `docs/INSTRUCTIONS.md` (detailed specs), `AGENTS.md` (repository-wide guidelines).
- **Tech Stack**: Rust 1.92 workspace using tokio, tonic/prost, clap, serde/serde_json, tracing, anyhow/thiserror, tower/hyper-util for CLI networking, `which`, `nom`, etc. Commands assume macOS host for broker and containerized Linux for CLI.
- **Notable Requirements**: Strict Unix permissions (`~/.op-broker` 0700, socket/config 0600), allowlist-only secret access, no secrets in logs, JSON CLI outputs shaped as `{ "ok": true/false, ... }`, proto updates via `tonic_prost_build` in `crates/protocol`.
